CASE 02 · 移动端

脑波灯配套 APP

把一台硬件设备的所有状态，压缩成一个普通人能看懂、能按的界面。

我的角色

产品负责人（需求定义 / 交互定稿 / 跨端对齐）

平台

iOS + Android（uni-app 双端一套代码）

版本

v1.0.0 → v1.0.4

CONTEXT

为什么需要它

脑波灯是硬件，用户拿到手第一件事是「怎么让它亮」，而不是「什么是脑波」。设备没有屏幕、没有按键说明，全部交互都压在手机上——所以 APP 本质上是这台硬件的「遥控器 + 说明书 + 内容入口」。

难点不在功能多少，而在三件事：一是蓝牙连接本身就是用户流失最大的地方；二是脑波数据对用户不可见，必须翻译成可感知的东西（灯光、声音）；三是冥想需要「放下手机」，界面越少越好，但配置项又不能少。

蓝牙连接不能成为门槛

硬件配网失败是退货率最高的原因。做了自动扫描 + 序列号兜底两条路径，并把信号强度、电量直接摆在界面上。

用户看不见脑波，只能看见光

脑波数据无法直接呈现，所以把「专注度」映射成灯光明暗与色温变化——用户看到的是一次呼吸，而不是一条曲线。

一段冥想必须能开始和结束

冥想是连续行为，一旦开始就要能一直跑；所以会话期间锁定界面、只留一个结束入口，避免中途误触。

PROTOTYPE

交互原型

下方原型为界面复刻，用于展示交互逻辑：真实版本依赖蓝牙硬件，无法在浏览器中运行。文案与配色取自原应用，已去除公司标识与品牌信息。

欢迎回来

登录后即可连接你的脑波灯，开始一次冥想。

登录即代表同意《用户协议》与《隐私政策》

可点击：选模式 → 连接设备 → 调灯光 → 选音效与时长 → 开始冥想

STRUCTURE

信息架构

三个模式 × 两种场景，一套设备管理，一个个人中心。刻意做减法：不做社区、不做课程商城，第一版只解决「连上、用起来、收得住」。

主模式

  • 冥想模式

    可调时长与音效，配合脑波引导进入状态

  • 助眠模式

    长时段白噪音 + 灯光渐暗，陪到入睡

  • 氛围灯

    不进入会话，只做纯灯光控制

使用场景

  • 个人模式

    单人使用，设备按个人偏好记忆

  • 团课模式

    多人同场景同步灯光，服务线下冥想课

设备管理

蓝牙扫描序列号绑定信号 / 电量断开与切换

账号体系

手机号登录账号与安全隐私与权限注销账号

DECISIONS

关键决策

每个决定都标明了代价。

问题我的选择理由与取舍

灯光颜色怎么调？

不做色盘，做四段式滑杆

做完调研发现用户说不出色号，只会说「暖一点」「蓝一点」。四段滑杆（暖橙 → 青绿 → 天蓝 → 柔紫）比取色器更快，也更容易被记住。

取舍：放弃了精细调色能力，进阶用户会觉得不够自由。

冥想中要不要显示脑波曲线？

不显示，只让灯呼吸

冥想的目标是「不看手机」。把数据翻译成光的变化，比给一条看不懂的曲线更有用，也更符合这个场景的心理目标。

取舍：少了科技感，销售端也少了一个可展示的卖点。

连接失败怎么办？

自动扫描 + 序列号手输双通道

蓝牙受机型、权限、系统版本影响极大，单一通道必然有用户卡死。序列号兜底让「最坏情况」也有解法。

取舍：多了一个输入框，界面没那么干净，客服话术也要多一套。

OUTCOME

结果与复盘

  • 双端一套代码交付，v1.0.0 到 v1.0.4 四个版本迭代，主要修的是连接稳定性与机型兼容。
  • 三模式结构上线后没有改过——说明这套「冥想 / 助眠 / 氛围灯」的划分是站得住的。
  • 如果重做：我会把「第一次连接」单独做成一个引导流程，而不是塞在首页的按钮后面。
  • 还会加一个「本次会话完成」的轻反馈——现在冥想结束是静默退出，用户没有完成感。
